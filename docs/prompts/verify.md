# 识机提示词 · 终版（v2.3）

> 用途：`lib/ai.ts` 的 `aiVision(imageB64, prompt)` 系统提示词。
> 主模型 glm-4v-flash，备选 qwen3-vl-plus（不是 qwen-vl-plus）。
> 返回结构对齐 `docs/README-dev.md` 的识机 API 契约，前端 `app/verify` 直接渲染。

## 一、当前生效版本（v2.3）

```text
你是数码产品验机专家。分析这张产品照片，只输出 JSON，不要任何多余文字：
{
  "category": "手机|耳机|相机|笔记本|平板|手表|其他",
  "model_guess": "最可能的型号名",
  "confidence": 0-100 的整数,
  "visible_defects": [
    {"area": "上左|上中|上右|中左|正中|中右|下左|下中|下右|屏幕|边框|背面|镜头|接口",
     "type": "划痕|磕碰|裂纹|污渍|屏幕老化|维修痕迹|进水痕迹|无",
     "severity": "轻微|中等|严重",
     "detail": "一句话描述"}
  ],
  "condition_score": 0-100 的整数,
  "notes": "补充判断，30字内"
}
若照片不是数码产品，输出 {"error":"not_product"}。照片模糊无法判断时 confidence 给低分并在 notes 说明。

判定口径（内部执行，不要输出推理过程）：
1. 划痕 vs 污渍：污渍有轮廓模糊、可覆盖面积、边缘渐变，且常呈聚集状；划痕是一条或数条线性高光/反光断点，有明确起止点与固定走向。无法区分的记为"污渍"并降 severity 一档。
2. 面积标定：以屏幕可视区为 100%，单条划痕长度 <5% 记轻微，5%~20% 记中等，>20% 或多条交织记严重。
3. 裂纹与碎屏：出现放射状纹路、玻璃掉块、漏液黑斑一律 type=裂纹 severity=严重。屏幕点亮区域出现色斑/残影但玻璃完整，type=屏幕老化。
4. 维修痕迹：螺丝滑牙、密封胶溢出、非原厂贴纸、排线折痕、后盖与中框色差，记 type=维修痕迹。
5. condition_score 锚点（同类照片必须落在同一档，误差 ≤3）：
   98~100 无可见瑕疵；90~97 仅 1 处轻微污渍/单条短划痕；
   80~89 轻微划痕 2~3 处或单处中等划痕；70~79 明显划痕/小磕碰多处；
   55~69 深划痕、边框变形、镜片划伤；30~54 裂纹但屏幕可显示；0~29 碎屏/漏液/无法开机迹象。
6. 有裂纹时 condition_score 上限 54；有进水痕迹时上限 49。
7. 避免"两端塌陷"：不要因为看到一处瑕疵就把整机判成 50 分以下；也不要在有明显瑕疵时给 95 分以上。
8. 照片模糊、反光过强、仅局部特写：confidence ≤ 45，notes 写明"照片模糊/反光，建议补拍正面平铺图"。
9. 只输出 JSON，第一个字符是 {，最后一个字符是 }，不要 markdown 代码块包裹。
```

## 二、模型分工与调用参数

| 项 | 主力 | 备选 |
|---|---|---|
| 模型 | `glm-4v-flash` | `qwen3-vl-plus` |
| endpoint | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` |
| temperature | 0.1 | 0.1 |
| top_p | 0.3 | 0.3 |
| max_tokens | 512 | 512 |
| 重试 | 失败重试 1 次后切备选 | 再失败返回 `{ error }` |

图片处理：客户端压到长边 1280px、JPEG q=0.82、base64 以 `data:image/jpeg;base64,` 前缀传入。超过 1600px 不压缩会显著抬高延迟（glm-4v-flash 实测 3~6s）。

## 三、后处理（服务端做，不信模型自觉）

1. `JSON.parse` 前先剥 ```json 围栏与前后空白；解析失败按「截取首个 { 到末个 }」再试一次。
2. `category` 不在枚举内 → 归 `其他`；`visible_defects` 缺失或空 → 补 `[{"area":"机身","type":"无","severity":"轻微","detail":"未见明显瑕疵"}]`。
3. `confidence`/`condition_score` 夹到 0~100 整数；`condition_score` 按第 5、6 条锚点回夹（有裂纹 ≤54、进水 ≤49）。
4. 返回 `{"error":"not_product"}` 时前端走「请上传数码产品照片」文案，不计入置信度统计。
5. 落库字段固定五项：`category / model_guess / confidence / visible_defects / condition_score / notes`，不新增字段。

## 五、回归用例（6 张，人工核对，每次改提示词必跑）

跑法：`python scripts/test_model_apis.py`（3 图自动跑并输出 PASS/FAIL），下列 6 条为人工补充核对的完整回归集。

### 用例 1 · 完好机
- 图：iPhone 13 深空灰，正面平铺白底，屏幕点亮，光照均匀，无膜或贴了全新高清膜。
- 期望：`category=手机`，`model_guess` 含 iPhone 13，`confidence ≥85`，`visible_defects` 为空或一条 `type=无`，`condition_score ∈ [95,100]`。
- 通过判据：连跑 3 次 condition_score 极差 ≤10 且全部 ≥95；不得出现「裂纹」「维修痕迹」。

### 用例 2 · 单划痕
- 图：同机型，屏幕右上 4cm 一条斜向细划痕，其余完好。
- 期望：`visible_defects` 恰好 1 条，`area=上右`，`type=划痕`，`severity=轻微`，`condition_score ∈ [86,95]`。
- 通过判据：不得判为 `污渍`（关键调优点）、不得判为 `屏幕老化`；连跑 3 次 type 字段一致率 100%。

### 用例 3 · 碎屏
- 图：右下角放射状裂纹，玻璃局部掉块，屏幕有漏液黑斑。
- 期望：`type=裂纹`、`severity=严重`、`condition_score ≤54`（实际应落 28~41）。
- 通过判据：3 次运行全部 ≤54 且 `severity` 均为「严重」；notes 提示「屏幕破损，属大修/功能缺陷档」。

### 用例 4 · 翻新痕迹
- 图：边框有撬痕、底部螺丝滑牙、后盖与中框轻微色差、贴纸有二次粘贴痕迹。
- 期望：至少 1 条 `type=维修痕迹`，notes 出现「拆修/翻新」字样，`condition_score ∈ [55,80]`。
- 通过判据：必须命中 `维修痕迹` 枚举，不得只描述为「划痕」；若同时出现进水痕迹则 condition_score ≤49。

### 用例 5 · 非产品图
- 图：一张人像合影 / 桌面咖啡杯。
- 期望：原始输出 `{"error":"not_product"}`。
- 通过判据：3 次运行均返回该错误体，且不夹带任何其他字段；解析层不得抛异常，前端文案走「请上传数码产品照片」。

### 用例 6 · 模糊图
- 图：夜间逆光、手抖、长边 640px 的机器照片，型号字样不可辨。
- 期望：`confidence ≤45`，notes 含「模糊/建议补拍」，`condition_score` 允许宽区间 [40,80] 但 3 次极差仍 ≤10。
- 通过判据：不得给出 `confidence ≥70` 的高置信度；不得返回 `not_product`（画面里确实是手机）。

## 六、已知缺口

- glm-4v-flash 对「压过外屏」这类仅靠缝隙气泡识别的瑕疵基本无感，需人工复核；提示词层无解，靠 `docs/prompts/report.md` 的 pitfalls 兜。
- 深色机身 + 强反光场景下划痕召回偏低，建议前端引导「斜 45° 打光再拍一张」。
- 模型不输出区域坐标，`visible_defects.area` 是九宫格 + 部件名的粗定位，不能当像素框用。
